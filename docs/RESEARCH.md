# Open-source research

Исследование обновлено 28 сентября 2026 года. Для credential-free discovery использованы архитектурные идеи MIT-проекта AEX-X/telescout; атрибуция зафиксирована в THIRD_PARTY_NOTICES.md. Основной SaaS, аккаунты, Mini App, тарифы и Railway-слой разработаны отдельно.

## TG Radar

- Репозиторий: https://github.com/bigidulka/tg-radar
- Лицензия: MIT.
- Полезные идеи: PostgreSQL как источник истины; идемпотентность на уровне БД; отдельные API/worker; деградация полнотекстового поиска без векторного индекса; бюджеты сбора; чтение публичных `t.me/s` без пользовательской сессии.
- Почему не форк: проект ориентирован на собственный индекс/агентов и Vespa, а SaaS MVP требует аккаунты, тарифы, проекты, bot UI и компактный Railway-деплой. Vespa слишком тяжёл для первого релиза.
- Что адаптировано концептуально: явная граница публичных данных, уникальность результата в рамках поиска, status lifecycle и PostgreSQL-first.

## Pulpit

- Репозиторий: https://github.com/giovabal/pulpit
- Лицензия: GPL-3.0.
- Полезные идеи: проекты исследований, поиск → crawl → анализ → export; граф пересылок/ссылок; PageRank и структурная аналитика.
- Ограничение: включение GPL-кода в закрытый коммерческий SaaS потребует соблюдения copyleft-условий. Код Pulpit не переиспользуется.
- Возможное развитие: собственная реализация графа связей поверх сохранённых публичных ссылок, либо отдельный открытый модуль.

## Telethon

- Репозиторий: https://github.com/LonamiWebs/Telethon
- Лицензия: MIT.
- Роль: MTProto-клиент, глобальный поиск сообщений и получение метаданных публичных сообществ.
- Риск: пользовательская сессия Telegram чувствительна и подвержена FloodWait/ограничениям. Нужны отдельный сервисный аккаунт, шифрование секрета, лимиты и backoff.

## MAX official SDKs and schemas

- Организация: https://github.com/max-messenger
- Документация: https://dev.max.ru/docs-api
- Deep links: https://dev.max.ru/docs/chatbots/bots-coding/prepare
- Вывод: webhook, команды, сообщения, mini apps и `?start=` официально доступны. Глобального API поиска чужих публичных каналов нет; сообщения доступны по `chat_id`, а история — когда бот администратор. Поэтому MAX используется как клиентский интерфейс, а не как несанкционированный scraper.

## Решение

Стек MVP: FastAPI + SQLAlchemy + PostgreSQL + Telethon + vanilla admin UI + Telegram/MAX webhook adapters. Он лёгкий для Railway и оставляет точки расширения для Redis worker, полнотекстового поиска, дополнительных законных каталогов и платежных провайдеров.
